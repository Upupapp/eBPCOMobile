## T-01 · Four subsystems are built, tested, and never called — HIGH

Each of these exists with tests and is referenced by nothing outside its own
file:

| Class | References in `lib/` |
|---|---|
| `CertificatePinner` | 1 — its own file |
| `SessionManager` | 2 — its own file, and a *comment* in `session_cleaner.dart` |
| `SyncEngine` | 1 — its own file |
| `OfflineQueue` | 2 — its own file, and `SyncEngine`, which is itself unreached |

`ApiClient` holds a plain `http.Client`: no pinner, no
`badCertificateCallback`, no `SecurityContext`. **So there is no certificate
pinning in effect.** `SyncEngine` is what drains the offline queue, so a
queued submission would sit there.

This is very likely deliberate staging — pinning needs the real host's
certificate, and a sync engine needs something to sync to, neither of which
exists yet. Both ADRs are careful and well-argued. **But neither says the code
is not yet wired, and nothing else in the repo does either.**

That matters most for pinning. A security control that is present in the
source and not in effect is worse than one that is absent: a reader, a
reviewer, or an auditor concludes the app is protected. Absent code invites
the question; dormant code answers it wrongly.

Fix: say so where it will be read — a line in each ADR and a `// Not yet
wired: see M-##` at each class — or wire what can be wired now. This is the
Android/Windows lane's code; the iOS lane raising it, not changing it.

## T-02 · The wizard progress header is copied sixteen times — FIXED

`_WizardProgressHeader` is defined once per wizard screen: fourteen with
byte-identical bodies once string literals are normalised, two with small
variants.

The cost is already paid rather than hypothetical. Fixing the 200% text-scale
overflow in S-06 meant a scripted edit across all sixteen; a shared widget
would have been one edit and one place to get wrong.

**Fixed 19 Aug 2026.** Extracted to
`lib/shared/widgets/layout/wizard_progress_header.dart`, parameterised on the
intro line. Net −1038 lines across the sixteen screens.

The duplication had already produced a real inconsistency, found while doing
this. The two variants differed only in how one string wrapped across source
lines, and that was enough for the scripted S-06 `maxLines` fix to miss both —
so Excavation and Certificate of Occupancy never received the bounding the
other fourteen did. They passed the accessibility suite anyway because the
title and subtitle bounding carried them. Extraction closed it for all sixteen
at once.

The extraction also went wrong before it went right: the first attempt
truncated each file at the header class, which deleted `_BottomActionBar`
below it in every wizard. `flutter analyze` caught it immediately; the redo
removes exactly one brace-balanced class block. Worth recording because "cut
from here to end of file" looked safe and was not.

The shared widget now has its own test, since sixteen screens depend on it,
and gained a semantics label — a progress bar is invisible to a screen reader
without one, and none of the sixteen copies had it.

## T-03 · The commencement threshold is stated twice — FIXED, and it was mine

`NotificationEvaluator.commencementWarningDays = 60` carries a comment saying
it "matches the Home action stack, so the two cannot disagree about what
'soon' means". `ActionItemBuilder` hardcodes `daysLeft <= 60` on its own.

They agree today by coincidence, and my comment claims a guarantee the code
does not provide.

**Fixed 19 Aug 2026.** `ApplicationModel.commencementWarningDays` is the one
home, beside `commenceByDate` — the rule it serves. Both consumers read it.

Related, though not duplication: `prcNeedsAttention` warns at 60 days and
`SavedDocumentModel.needsAttention` at 30. Both are deliberate and reasoned in
their own files, but there is no one place a reader can see the app's
warning thresholds together.

## T-04 · `flutter_svg` is declared and never used — FIXED

No import anywhere in `lib/` or `test/`, and no `.svg` in `assets/`.

Worth removing rather than leaving: every dependency is compiled for both
platforms and can raise an OS floor as a side effect, which is exactly how the
iOS floor moved to 15.0 in S-04. A package that does nothing should not be
able to do that.

**Removed 19 Aug 2026.**

## T-05 · Accessibility still covers 3 screens plus the wizards — FIXED

S-06 added the sixteen wizards and all sixteen shared widgets. The screen-level
suite still named only `DashboardScreen`, `NotificationsScreen`, and
`CitizensCharterScreen`.

**Fixed 19 Aug 2026.** `test/accessibility_screens_test.dart` covers the seven
that were missing — `ApplicationListScreen`, `ApplicationDetailScreen`,
`OrderOfPaymentScreen`, `PaymentHistoryScreen`, `ProfessionalsScreen`,
`PreFlightScreen`, `PrivacyDataScreen` — at 100%, 200% text scale, 320dp, and
against the 48dp touch floor. 28 cases.

The prediction in the original entry held: composition was where the defects
were. Four failed on first run, and one of them fails at **normal text size on
a 320dp phone**, which is a shipping bug rather than an accessibility edge.

### Two defect families, five sites

**Money rows.** `Expanded(label)` beside an unbounded amount `Text`. `Row`
lays the unbounded child out first at its natural width and hands `Expanded`
the remainder — which at 200% was three and a half pixels, so the label
overflowed. Ellipsising is not the fix: these are fee names and centavo
amounts on a document the applicant pays against, and money must never be
truncated.

Extracted `lib/shared/widgets/layout/amount_row.dart`, which reflows the
amount onto its own line instead of shrinking either side. A `Wrap` makes that
decision, so there is no text-scale threshold to get wrong — the amount moves
exactly when it does not fit, at any scale and any width. Four call sites
across the two payment screens.

**Status pills.** `StatusBadge` has existed in `lib/shared/widgets/badges/`
the whole time. Five sites hand-rolled it anyway, and all five put the pill in
a `Row` as an unbounded sibling of an `Expanded` title — the same shape, the
same failure. The hand-rolled copies also lacked the
`Semantics(label: 'Status: …')` the shared widget carries, so every one of
them was a status invisible to a screen reader.

Replaced with `Flexible(StatusBadge(...))`, which is what
`shared/widgets/cards/tracking_card.dart` already did and why that card never
failed.

Only two of the five were caught by the new screen tests. The other three
passed because the fixture's status labels happened to be short enough — they
are latent, not absent. That is why the fix came with
`test/architecture/status_badge_usage_test.dart`, which scans `lib/features`
for the shape rather than waiting for a fixture long enough to trip it. It
flags 4 sites at the pre-fix commit and none now.

Also worth recording: `dart format lib/` reformatted ~230 files, most of them
the Android lane's, because the repo is not formatted to the current
`dart format` style. Format single files, never the tree.
