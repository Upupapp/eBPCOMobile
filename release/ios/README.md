# iOS release — Mac lane

Owned by the macOS agent. See `../../LANES.md`.

The Android lane must not edit this directory, and this lane must not edit
`release/android/` or `android/`.

## What lives here

| File | Purpose |
|---|---|
| `NOTES.md` | Running log of builds, version/build numbers, and submission outcomes |
| `ExportOptions.plist` | Archive export configuration — added when the first archive is made |

Nothing here is generated by a build. Xcode output goes to `build/` and is
gitignored.

## State

Never archived and never submitted. The app runs on the simulator; there is no
distribution certificate, no provisioning profile, and no App Store Connect
record. Bundle identifier is `com.ebpco.ebpcoUserApp`, a development
placeholder — see M-29, which must be settled *before* the first submission
because it cannot be changed afterwards without losing the listing.

## Running locally

```bash
open -a Simulator
flutter run
```

The first iOS build takes several minutes while Xcode fetches Swift Package
Manager dependencies for the image picker and cropper. Later builds are quick.

## Before the first submission

These are prerequisites, not steps I can perform — each needs an Apple
Developer account and the owner's credentials.

1. Settle the bundle identifier (M-29).
2. Resolve the deployment target (M-38): the floor is 15.0 because the plugin
   set raised it, not because anyone chose to drop iOS 13 and 14.
3. Create the App Store Connect record and set a development team in Xcode.
4. Provide the privacy nutrition label. The app collects government IDs and
   proof-of-ownership documents, so the answers are not the defaults.
5. Prepare App Review notes with the demo login, since the app is behind
   authentication and a reviewer cannot see past it otherwise.

## Archiving, once the above exists

```bash
flutter build ipa --export-options-plist=release/ios/ExportOptions.plist
```

Then upload with Transporter or `xcrun altool`. Neither is run by this agent.
